# Smart Campus Analytics: Student Success Platform

A secure, role-based platform that brings a college's scattered student data into one profile per student. For each student it:

- calculates an explainable Success Score
- flags academic and placement risk separately, with the evidence and rule behind every flag
- tracks interventions through to their outcomes

It is built to run on the **AWS Free Tier**: Cognito for sign-in and roles, least-privilege IAM, Lambda, S3, DynamoDB and CloudFront.

> All student data in this repository is **synthetic** (generated by `ssp/synth.py`). No real student information is used.

## Quick start (local, no AWS needed)

```bash
pip install openpyxl                 # the only runtime dependency
python -m ssp.seed --reset           # synthetic data, 43 demo users, scores, interventions
python -m ssp.server                 # http://127.0.0.1:8080   (add --tls for HTTPS)
python -m unittest discover -s tests -v
```

## Deploy to AWS (free tier)

```bash
pip install boto3
python deploy/deploy.py --region ap-south-1 --seed
```

The script:
1. creates the CloudFormation stack in [`deploy/template.yaml`](deploy/template.yaml)
2. uploads the Lambda code, a 300 KB pure-Python bundle
3. publishes the frontend
4. with `--seed`, loads the demo data

Demo users are created in Cognito with random passwords, written to `deploy/.demo-credentials.json` (git-ignored). The deploying identity needs the permissions in [`deploy/deployer-policy.json`](deploy/deployer-policy.json).

```
Browser ──HTTPS──▶ CloudFront ──▶ S3 (private, OAC)          frontend
   │                   └─/api/*─▶ Lambda function URL          API (Python 3.12, arm64)
   │                                   ├─▶ S3 (private, SSE)       records, uploads, score snapshots, rule versions
   │                                   ├─▶ DynamoDB (5/5 RCU/WCU)  interventions, upload log, audit log, locks
   │                                   └─▶ Cognito (admin APIs)    user management
   └──OAuth code + PKCE──▶ Cognito hosted sign-in (Lite tier, optional TOTP MFA, role groups)
```

| Component | Why it costs nothing |
|---|---|
| Cognito user pool (Lite) | Free up to 10,000 monthly active users; TOTP MFA has no SMS cost |
| Lambda + function URL | 1M requests and 400,000 GB-seconds a month are always free; no API Gateway |
| DynamoDB | Provisioned 5 RCU / 5 WCU, inside the always-free 25/25; AWS-owned encryption key |
| CloudFront | 1 TB and 10M requests a month are always free |
| S3 | A few MB of data. Free for the first 12 months, then about US$0.01 a month |
| CloudWatch Logs | 14-day retention, far below the 5 GB free allowance |

There is no NAT gateway, VPC endpoint, KMS customer key, API Gateway or always-on server.

## How it meets the requirements

[`docs/requirements-traceability.md`](docs/requirements-traceability.md) maps every requirement to the code and the test that proves it. In brief:

- **Roles and authorisation.** Administrators, HODs, faculty mentors, placement officers and students each see only their scope. The server enforces this on every request in `ssp/access.py`, so it doesn't depend on hiding things in the UI.
- **Data integration.** CSV or Excel uploads go through two steps:
  - Each file is first checked for field types, formats and ranges. Duplicates, unmatched IDs and blank values are flagged, and a summary shows what would be accepted or rejected.
  - Only then is it imported, as upserts on the natural key, so re-uploading changes nothing. A failed import leaves the existing records untouched.
- **Success Score.** 23 indicators across 7 pillars, each normalised against fixed reference values and weighted, with the exact points each one contributes.
  - Missing data is excluded, never counted as zero, and low data coverage makes a score provisional.
  - Indicators apply only to the years and courses they suit.
  - The scoring-rules version is recorded with every score.
- **Risk.** Academic and placement risk come from separate configurable rules. Each flag shows its evidence and source file, and "Insufficient data" is a distinct state from "Low". Scores are recalculated automatically after every import.
- **Interventions.** Each suggested action is linked to the rule that triggered it. Staff assign an owner, due date and review date, then track status, notes and the outcome. Overdue items are highlighted, and progress is compared between review periods.
- **Audit and reliability.** Uploads, scoring changes, intervention updates, sign-ins and profile views are all logged. A lock prevents concurrent imports, and every write of records is atomic.

## Layout

```
ssp/            backend (shared by Lambda and the local server)
  api.py          routes; every handler authenticates and authorises
  auth.py         Cognito RS256 token verification, local login, user directory
  access.py       role scopes, field redaction, intervention permissions
  importer.py     validate → stage → commit, with idempotent upserts
  schemas.py      upload templates: fields, types, ranges, header aliases
  features.py     records → per-period indicators, with provenance
  engine.py       score, risk rules, segments, actions, versioned snapshots
  interventions.py, summary.py, audit.py, storage.py (S3/DynamoDB or local)
  synth.py, seed.py, validate.py   synthetic data, demo seeding, outcome validation
config/         scoring.json (rules, weights, thresholds); validation_report.json
web/            frontend (no framework, no CDN)
deploy/         CloudFormation template, deploy script, deployer IAM policy
data/sample/    synthetic upload files: current terms, demo files, historical batch
tests/          30 tests; AWS mode tested against moto
```
