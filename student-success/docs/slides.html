Smart Campus Analytics

From scattered records to a follow-up on every at-risk student

A secure, role-based Student Success Platform. It brings seven data sources into one profile per student, explains every score and risk flag, and tracks each intervention through to its outcome. It runs entirely on the AWS Free Tier.

Step 1 · Upload

Every file is checked before anything changes

  • CSV or Excel for academic results, attendance, LMS, engagement, placement tests, skills and feedback
  • Four spellings of a roll number are matched to one student ID
  • Checks field types, formats and ranges, plus rules such as "attended ≤ held"
  • Flags duplicates, conflicting rows, IDs missing from the roster, and blank values
  • Shows a summary first: accepted, rejected, new, changed and unchanged rows
  • Uploading the same file again changes nothing; a failed import changes nothing
  • Each row keeps its source file, reporting period and update time

Step 2 · Score and flag

Every point and every flag can be traced to a source record

  • Success Score: 23 indicators in 7 weighted pillars, each normalised to 0–100. The points per indicator add up exactly to the score
  • Missing data is excluded, not counted as zero. Coverage below 75% makes the score provisional; below 40% it is withheld
  • Separate academic and placement risk, from configurable rules. Each flag lists the value, the threshold and the source file
  • "Insufficient data" is not "Low", and it suggests collecting the data
  • Rules are versioned. Changing them re-scores everyone and keeps old results

Step 3 · Prioritise

The dashboard shows who needs attention, and why

  • Filter by department, course, year, cohort, risk level and segment, or search by name or ID
  • Separate academic and placement risk views; click any part to list those students
  • "Need review" catches high risk with no action, overdue actions, declining trends and missing data
  • Trends across review periods, months and weeks
  • Data freshness for every source
  • Seven segments, each with an owner and a playbook, including "Strong academics, low placement readiness"
Dashboard · segmentation6
Step 4 · Act and follow up

Suggested actions become tracked interventions

  • Each suggestion is linked to the rule that fired, for example A-ATT-SHORT leading to an attendance recovery plan
  • Staff pick an owner, due date and review date
  • Status moves Open → In Progress → Completed, with notes; completing requires an outcome
  • Overdue actions are highlighted on the dashboard and in the list
  • Progress compares the score when the action was opened with the latest review
  • A summary is drafted from the student's own records only; staff review it before saving

AUC 0.95 for the Success Score against poor academic outcomes, and 0.79 against not being placed. AUC measures how well a ranking separates outcomes: 1.0 is perfect, 0.5 is chance.

Students with no placement test on record did markedly worse than those flagged Low. That is why missing evidence triggers an action instead of reassurance.

Trust

Private, auditable and reliable by design

  • Privacy: scoping and field redaction happen on the server; profile views are logged
  • Security: TLS everywhere, with non-TLS requests to S3 denied; data encrypted at rest; passwords held by Cognito; strict browser security headers; one least-privilege IAM role
  • Audit: uploads, rule changes, recalculations, interventions, user changes, views and exports
  • Reliability: files are checked before import; each write is atomic; an import lock prevents clashes; failed imports can be retried; S3 versioning
  • Maintainability: every weight and threshold lives in one versioned, validated file
  • Tested: 30 automated tests, including the AWS paths against simulated AWS

All data shown is synthetic, generated to mimic real campus exports. No real student information is used.
